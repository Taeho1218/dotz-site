A family care app for medication. An adult child who lives far from their parents registers the parents' medicines and sees, in real time, whether each dose was taken. The parent's side is one large button: "I took it." 가족 케어 복약 관리 앱입니다. 멀리 사는 자녀가 부모님의 약을 등록하고, 복용 여부를 실시간으로 확인합니다. 부모님 화면에는 큰 버튼 하나, "복용 완료했어요"만 있습니다.

02 How we work with ClaudeClaude와 일하는 방식

The agents do the work. A person decides what leaves the building.일은 AI 직원이 하고, 밖으로 나가는 일은 사람이 정합니다.

dotz runs on Claude Code. The main Claude session acts as chief of staff: it splits work between specialist agents, collects their reports, and asks Taeho for approval. The rules below are written down and the agents load them every session. This is how several apps are maintained and updated at the same time. dotz는 Claude Code로 돌아갑니다. 메인 Claude 세션이 실장 역할로 일을 직원들에게 나누고, 보고를 모으고, 태호에게 승인을 받습니다. 아래 규칙은 문서로 적혀 있고, 직원들은 세션마다 이를 불러와 따릅니다. 이 방식으로 여러 앱을 동시에 유지하고 업데이트합니다.

  1. Direction방향Taeho sets the goal and the constraints for a team.태호가 팀의 목표와 제약을 정합니다.
  2. Chief of staff실장The main Claude session assigns work and calls the right agent.메인 Claude 세션이 일을 나누고 알맞은 직원을 부릅니다.
  3. Staff직원Agents draft, build or research, then report with a three-line retrospective.직원이 초안·구현·조사를 하고, 회고 3줄을 붙여 보고합니다.
  4. Approval승인Posting, sending, payment, store submission and release wait for Taeho. Confirmed again right before running.게시, 전송, 결제, 스토어 제출, 출시는 태호 승인을 기다립니다. 실행 직전에 한 번 더 확인합니다.
  5. Record기록The session is saved as a worklog; approved items enter the wiki.세션이 작업일지로 저장되고, 승인된 내용만 위키에 들어갑니다.

Loop순환 The next session starts from the wiki and the team's handoff file, and the weekly review feeds changes back into the agents' manuals.다음 세션은 위키와 팀 인계서에서 시작하고, 주간 검토가 직원 매뉴얼을 고치는 데 쓰입니다.

ASpecialist agents역할별 AI 직원

  • Planning lead기획팀장Research and validation; writes and updates the seven-document spec for each app.리서치와 검증, 앱마다 기획서 7종 작성·갱신.
  • Designer디자이너Screen structure, design direction, design and accessibility review.화면 구조, 디자인 방향, 디자인·접근성 검수.
  • Marketer마케터Drafts posts and analyzes channel insights. Has no posting tool.게시글 초안과 채널 분석. 게시 도구가 없습니다.
  • Ops and settlement운영정산Open tasks, risks, pre-release checklists, weekly team report.남은 일, 위험, 배포 전 점검, 주간 팀 보고.
  • Researcher리서처Collects outside material, grades its reliability, proposes improvements.외부 자료 수집, 신뢰도 등급, 개선 제안.
  • Developers개발Claude Code agents for implementation, code review and verification.구현, 코드 리뷰, 검증을 맡는 Claude Code 에이전트.

One manual per role, shared across teams. Each app has its own team charter (product, customer, tone, goals, what not to do).직무 매뉴얼은 역할마다 하나를 공용으로 쓰고, 앱마다 팀 헌장(제품, 고객, 톤, 목표, 금지 사항)을 따로 둡니다.

BHuman approval rules사람 승인 규칙

Agents may draft, but anything that goes outside gets approved first: posts, messages, payments, store submissions, releases. Agents also may not delete files (they move them to a holding folder), sign up for or pay for services, read secret files, or contact customers.직원은 초안까지만 씁니다. 게시, 전송, 결제, 스토어 제출, 출시처럼 밖으로 나가는 일은 먼저 승인을 받습니다. 직원은 파일을 지우지 않고(보류 폴더로 옮김), 서비스에 가입·결제하지 않고, 비밀값 파일을 읽지 않고, 고객과 직접 소통하지 않습니다.

Limits are enforced by tooling where possible: the marketer simply has no posting tool.가능한 한 도구로 제한합니다. 마케터에게는 게시 도구 자체가 없습니다.

CMemory that carries across sessions세션을 넘어 이어지는 기억

Knowledge lives in a markdown wiki: operating rules, project pages, research. When a session ends, a hook saves a worklog to a pending inbox; at the next start Taeho decides whether it enters the wiki. Each team keeps a handoff file that is loaded automatically when a session opens, along with the tail of the previous conversation. Rule changes at headquarters are pushed to running team sessions.지식은 마크다운 위키에 있습니다. 운영 규칙, 프로젝트 페이지, 리서치입니다. 세션이 끝나면 훅이 작업일지를 승인 대기함에 저장하고, 다음에 열 때 태호가 위키에 넣을지 정합니다. 팀마다 인계서가 있어 세션을 열면 자동으로 읽히고, 직전 대화의 끝부분도 함께 불러옵니다. 본사에서 규칙이 바뀌면 열려 있는 팀 세션에도 전달됩니다.

DWeekly self-review주간 자체 검토

Every report ends with three lines: what went well, what got stuck, what to change in the manual. Once a week the retrospectives, agent memory and the researcher's proposals are gathered, and the proposed edits to agent files and guidelines are shown as a diff. Only what Taeho approves is applied, and the old text is kept in a change log. Agents never edit their own manuals; they only propose.보고는 모두 회고 3줄로 끝납니다. 잘된 것, 막힌 것, 매뉴얼에 고칠 것입니다. 일주일에 한 번 회고와 직원 기억, 리서처의 제안을 모아 직원 파일과 지침서의 수정안을 diff로 보여 주고, 태호가 승인한 것만 반영합니다. 이전 내용은 변경 이력에 남깁니다. 직원이 자기 매뉴얼을 스스로 고치지는 않고 제안만 합니다.

EResearch reliability grades리서치 신뢰도 등급

AOfficial docs, primary sources, named press. Can be the basis for a rule.공식 문서, 1차 자료, 실명 언론. 지침의 근거로 쓸 수 있음.
BReproducible hands-on reports (dates, code, figures). Trial first, then adopt.날짜·코드·수치로 재현되는 실사용 후기. 시범 적용 뒤 반영.
CClaims only, or selling a course. Marked as a claim, reference only.주장뿐이거나 강의 판매용. "(주장)"으로 표시하고 참고만.

Unverified figures carry an "unconfirmed" tag. Sources with no date count as C.확인 안 된 수치에는 "(확인 안 됨)"을 붙이고, 날짜가 없는 자료는 C로 봅니다.

FA second model checks before release출시 전에 다른 모델이 한 번 더 봅니다

Before store submission, and for sign-in, payment and personal-data code, agents recommend a read-only review by a different model, because the same model tends to miss the same things. Taeho approves each run, and the findings are checked against the code before anything is changed.스토어 제출 전이나 로그인·결제·개인정보 코드에는 직원이 다른 모델의 읽기 전용 검토를 추천합니다. 같은 모델은 같은 곳을 놓치기 쉽기 때문입니다. 실행은 태호가 승인하고, 지적 사항은 코드로 확인한 뒤에야 반영합니다.
